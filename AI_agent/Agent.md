## 产品与质量

- BIM Agent = work model + harness；harness = runtime + domain。runtime 与建筑无关；domain 含 BIM rules、kernel、tools、methods、roles、guidance。
- 统一产出源 BIM；还原、部分推理、完全推理按信息充分程度区分，不拆成三套产品。
- 当前 domain 按可复用能力组织，入口见 [domain 导航](../src/agent/README.md)；旧阶段管线与资源在 legacy，不作为新任务的步骤或 skills。
- 当前首要目标是让 harness 充分且必要：向模型提供可发现、可读取的依据和当前状态，由代码承担确定性计算、状态维护与检查，只让模型承担感知、证据取舍和推断。快速、稳定交付是检验结果，不能靠省略必要判断或增加机械手续换取指标。
- 用户明确长期目标为本地部署和快速交付，不绑定27B。2026-10-19按追加授权完成国产Flash一平一立粗测后收工：DeepSeek/Qwen北立面单样本通过，平面未得到可替代6 Sol的成功结果，MiMo/GLM另有传输或元数据失败。读图员与27B线暂存，下一轮转向搭建textured mesh harness。候选不局限本地级，优先更快、更低服务档位和整任务成本；上限测试与速度优化分别评价，不为固定模型增加特殊流程。具体批次启动前列明模型、范围和预算，不把候选清单写成已授权运行。
- Work model 不设国别、规模或型号上限；当前主线使用 GPT-6 Sol（`gpt-6-sol`），不以6.1 Sol替代。2026-10-18用户明确：在既定Lite精度和空间关系正确的前提下越快越好，平面读图目标3–4分钟，不能用不必要的精细化换取更长耗时；整案5分钟是优化目标，不是质量硬截止。分工读图并发保留runtime默认8，任务不足8时按实际任务数并发；上次整案的2是测试配置，不是runtime限制，未来降并发需有明确理由。缓存参数不动。当前单模型支持无整案时间截止，分工入口仍要求有限时间预算。照片路径先沉淀已有原型，不新增试验。
- 优先保证建筑空间划分与关系：漏墙、多墙、错拆错并、假楼板、门窗挂错与连通改变属于实质错误。
- 当前图纸主线按分工设计，默认6 Sol，调度员/平面读图员high、立面读图员medium；平面、立面先产二维结构化读图，组装再物化源BIM。读图员负责数值、实际图和回叠的局部正确性，调度员负责图种/任务分配、公共坐标/楼层、跨图冲突和建筑合理性。共同原点要区分整楼包围盒极值与实体墙角，不让各层自选。2026-10-18起新正式平面读图逐墙填写1cm厚度，允许有依据的批量推断；类别默认作为inferred，逐段直接依据可作为observed。外墙默认外包向内展开，内墙默认中线；例外可按原图上下左右指定材料展开方向，代码转换坐标侧别。同一墙带只画一条参考线，不把两面或墙体内部当成额外墙/zone。代码以2倍较大墙厚筛选同墙候选，选已有锚点后上10cm网格，不平均；同层在trial处理、跨层在组装处理。净图渲染厚度，回叠默认显示同一采用几何的参考线，人工检视页可切换墙带；原读数和移动审计保留。具体契约及最小单元见[墙厚与同墙合并](design/lite_wall_thickness.md)，实测边界以当前交接为准，不能把完整属性覆盖等同测量准确。用户要求尽量减轻读图员负担，可牺牲一定位置精度；复杂管井语义本轮不处理。现已完成一次分工整案及后续读图减负小批；本轮收工暂存该线，质量边界与恢复入口见当前交接。
- 规整首先减轻模型负担。明确标注或实际几何中的细数值也允许规整到10 cm，保留原读数与采用值依据。整图标注自动选步长仍待设计。
- 信息不足可以明确推断、假设和简化；不能把推断说成实测。GT留在评价侧。
- 源空间简化与后端热区合并分开。EnergyPlus跑通或单元测试通过不代表图纸保真。
- 正确性与合理性是分开的能力职责：读图阶段完成局部原图保真，组装阶段复用已完成检查，调度阶段判断整栋合理性；无具体冲突不例行重读全套原图。调度员仍可获取完整信息并机动处置，不能为提效增加信息硬隔离。6 Sol→Haiku→27B及追加国产Flash小批均已结束，当前读图员与整案迭代均暂缓，不自动扩大到全图。正确性由读图员自审还是其他模型审、是否增加组装员，留待恢复该线时讨论。细节见当前交接。

## 执行与边界

- 用户当前指令优先。正常技术选择、可逆修复、按影响的离线验证、Git提交和正常推送已授权，不反复确认。
- 模型实测遵守本次任务的明确范围。DeepSeek每次/每批必须另获明确许可；不得自动回退到付费API。ChatGPT授权与切号依据用户当前指令，账号由用户在浏览器内选择；账号授权不自动扩大真实模型测试范围。
- GLM订阅可按已授权的测试范围使用；历史额度或旧实验授权不自动授权新整案。真实模型节点回归由项目经理提出具体方案后执行用户批准范围。
- 测试依据当前产品要求。废弃设计对应检查退出，不写兼容层维护旧文件字节、函数结构或措辞冻结；当前数据完整性、权限、记账与几何性质仍须验证。
- 不以收工、换助手、文档改动为由重复全量。只读回看、确定性重放、真实模型调用分别报告。
- 接手未完成改动先查状态，保留未知改动。不得强推共享Git历史或丢弃独有证据。

## 目录与收尾

开发主库为 `D:\Sim-BIM-Agent\repo`；短期工作树放 `D:\Sim-BIM-Agent\worktrees`。桌面是发布产物，不存开发缓存、测试、GT和历史实验。新数据/运行/缓存位于D盘同级目录；历史资料保守留在D副本原位但不进入当前Git树，准确位置见归档索引。

桌面固定为 `Sim BIM Agent`，以后使用 `scripts/release/update_product.ps1` 原位更新/回滚，不再创建版本后缀目录。用户要求本地保持简单：D盘只保留上一版的程序压缩包和状态记录，排除虚拟环境、案例和输出；更早版本交给Git。临时发布与更新副本验证完成后清理。

本轮任务完成后保存简短交接与验证边界，核对diff、commit/push、清理已完成工作树，报告C/D剩余空间。用户要求的独立审阅须在实施完成后另启审阅者，发现问题修复后复核。项目事实保存在仓库，助手记忆只作索引。

每次测试正文给可读结果表，说明范围、版本、结果、耗时、调用/用量、失败和未覆盖项。真实建模另报空间/几何质量、5/10/30cm分档、角色行为及平面/回叠/BIM入口；缺项明确写未生成或未评。
