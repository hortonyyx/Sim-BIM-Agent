# 当前架构

Sim BIM Agent = work model + harness；harness = runtime + domain。单模型与分工共用源 BIM、几何能力和工具。模型与输入策略见 [讨论结论](../project/model_and_input_strategy.md)，版本与实际验证状态见 [roadmap](../project/roadmap.md)。

## Runtime

`src/agent_runtime` 负责模型适配、请求与工具循环、上下文、事件/产物、用量/预算、暂停/恢复、委派与连接；公共类型在 `src/harness_contracts`。它不定义建筑判断，也不要求任务经过固定编号阶段。

每次运行记录模型配置、runtime/domain 版本及提交，持久化事件、产物与恢复点。服务连接、目录访问和真实推理分别验收；缺失 usage 不由估算补成供应商实报。

## Domain

| 组成 | 职责 | 当前主要实现 |
|---|---|---|
| BIM rules | 源 BIM、依据、声明、检查与修改约束 | `src/agent/contracts`、`geometry/source_bim.py` |
| kernel | 编译、空间关系、规整、装配和开口宿主计算 | `src/agent/geometry` |
| tools | 看图、量测、试建、编辑、检查和交付 | `scripts/tool_scripts/run_bim_agent.py`、`bim_agent_*.py` |
| methods | 按输入及任务组合的处理方法 | 图纸方法、mesh 观察工具及输入专用 guidance |
| roles | 职责、可见工具、上下文与产物契约 | `src/agent/runtime_roles` |
| guidance | 系统指引、任务说明、参考资料、工具说明和反馈 | `bim_agent_guidance.py`、`runtime_roles/guidance.py` |

Methods 是可复用方法，不是固定阶段；roles 是任务分工，不与三条研究线一一对应。三条线描述相对于交付目标的信息充分程度，同一项目可以组合不同输入和能力。

现有分工实现为调度员、平面读图员和立面读图员；单模型使用同一套源BIM与工具。当前以role_division为主线，6 Sol调度/平面high、立面medium，已完成一次自主整案。用户目标是在既定Lite精度下越快越好，平面3–4分钟、整案约5分钟为优化目标。runtime读图默认并发8；上次整案配置2不代表runtime降级。正确性与合理性分开负责，具体由哪个模型核验、是否增加组装员后续再议。当前只有单模型支持无整案时间截止，分工入口仍要求有限seconds。

完整草稿、几何与审计留在外部状态，模型通过有界对象读取与局部修改操作。压缩后的证据还必须可发现，不能仅因磁盘保留就认为模型可用；旧版本来源与当前候选要明确区分。调度员保留完整信息获取与机动判断，效率改进作用于默认呈现和流程，不以硬隔离限制其权限。图纸读图员与整案迭代暂缓，2026-10-19已开始mesh方法首批搭建，入口与验收相对独立，共享通用BIM及可复用能力。单模型mesh已接入辅助PNG与文字声明；当前图纸分工仍未实现该混合输入调度。

## 输入与交付

2026-10-19 mesh复用single_model入口和相同runtime，调度员自主选工具，可选开启同模型只读worker。`runtime_mesh_workers.py`只承担domain派工与证据语义；子任务复用公共Runtime/EventStore、根预算和恢复，不另建循环。任务输入按原字节复制，候选只给明确source快照；worker在自己的目录生成视图、回叠和测量，主BIM仍由调度员修改。父子结果与用量可分别核查，已完成任务复读不重复请求，变更参数/版本/证据不能冒充同一任务续跑。

`source_polygon_v1`通过显式`simple_polygon`合同使用公共源BIM builder，支持简单直边/凹多边形、斜宿主开口和已有退台/跨层关系；旧schema不变，曲线、孔洞、斜墙面、空间变截面及EnergyPlus仍不支持。Mesh回叠默认按源几何朝向/遮挡显示，可按真实source boundary ID选择宿主；完整投影复用不可变报告分页。它不代表原mesh拟合或独立精度通过。`finish_bim`保存mesh范围声明并绑定当前源模型、原mesh和回叠证据，只有有效整栋声明允许完成；worker完成不代替该判断，图纸楼层覆盖字段保持独立。首批几何见[首批交接](../reports/2026-10-19_textured_mesh_harness_first_build.md)，worker接线见[后续交接](../reports/2026-10-19_textured_mesh_workers.md)。

平立面图纸是当前 harness 的主验证输入。单模型接收图像或 GLB，图像可声明 drawings/mesh_views/photos/unknown；分工入口仅支持图纸。接收输入不等于已达到稳定建模质量。[照片→mesh→BIM](photo_to_mesh_bim.md) 已有独立、有开发代理介入的原型，并已转换为项目源格式；照片生成服务尚未接入自主 harness，细度自动选择尚未实施。

核心交付为源 BIM：空间、边界、门窗、相邻/连通与依据；查看页由 `render_geometry_viewer.py` 及随包资源生成。源空间简化与后端热区划分分开，EnergyPlus 是可选下游。

当前主线为6 Sol分工：公共坐标与楼层约定 → 平/立面结构化读图、二维采用值图和局部原图回叠 → 不可变读图交付 → 平立面匹配、层高与门窗高度应用 → 整楼建筑合理性 → 必要时定向返工 → finish交付。局部正确性在读图阶段完成，调度员复用检查，按需回看原图。domain111明确平/立面任务图种并分别提供参考资料，立面坐标不再引用平面北针；普通编辑和备注细则按需获取，读图审阅结论支持文本或summary对象并绑定相同视图哈希。调度员与单模型的提示、工具和能力指纹未变；单模型保留 `process_reviews: true` 作为实验入口。

当前开发版domain113保留上述精简指导，读图入口按像素顺序成对归一化Z锚点，参考主题类型错误返回可纠正错误；domain112加长的参考线保留提示因实测未显示提速而撤回。最终版本尚未全图复测，固定桌面仍domain110，不能将开发变更等同成熟稳定发布。

`reader_task`（CLI `--reader-task-json`）通过相同 RoleSession、权限、预算和事件记录只运行一个明确读图任务，跳过调度员模型和整案自动补齐。输出明确为 reader_unit，不能当整楼交付。平面 `reading_type=plan` 交付二维墙线、房间、开口宿主、厚度与依据，生成净图/回叠但不生成源BIM，未知高度允许省略；组装引用已接受立面确定高度后才生成源BIM，缺失高度只能在组装侧明确作假设。立面 `trial_elevation_reading` 先保存采用值、净图和原图叠图，`submit_elevation_reading` 引用当前试稿并附 `local_review.summary`。检查与产物哈希绑定，图像改动或旧稿不能静默复用；自报检查不等于独立质量验收。调度员 `finish_bim` 携带 `architectural_review.summary`，绑定实际源几何。读图接受与完整finish均自动结束相应任务，不额外请求结束语。

公共坐标说明使用共同测量基准或整楼包围盒的西/南极值，不能只含糊写“西南外角”。L形的包围盒原点可能位于实体之外；各层与各立面保留局部退台/凸出相对该原点的偏移，不独立改用实体拐角。这是任务基准约定，不是墙带匹配或自动移墙。

正式平面读图要求每段墙有正厚度，按1cm登记，允许有依据的类别默认和局部覆盖；类别外推作为inferred，逐段直接依据可标observed，原声明保留。外墙默认外包向内，内墙默认中线；单侧例外可用原图up/down/left/right指定材料展开，代码结合标定转换为规范参考侧。厚度与依据随源BIM及几何编辑维护。厚度参与同层及跨层候选匹配，阈值为2倍较大墙厚；选已有锚点再上10cm网格，不取平均，保留分段厚度和移动审计。跨层只对齐XY、保留各层Z。同一墙带只需一条参考线，厚度不替代空间拓扑、门窗宿主和连通判断。

二维净图渲染墙带并保留开口空隙；默认回叠显示同一采用几何的细参考线，避免遮挡原图，人工review.html可切换墙带回叠。每次试读仍只向模型返回回叠和净图两张图。原图、采用值、产物及实际视图哈希绑定；厚度改变使净图变化时，旧观察不能复用。局部墨线差异只是复看提示，不等于自动识别错误或完成独立质量验收。

读图工具保留原图像素尺度及实际图尺寸。实际平面回叠以灰度显示原图、以颜色显示采用结果，原图输入保持；外窗序列及跨度仍由读图员在这一次回叠中核对，局部墨线报告为空不等于外窗已验。尺寸链tick_pixels接受标量或原图[x,y]点，代码按axis取坐标；拒绝时可并列报告同一份原稿在未对齐、未规整状态下的断接，避免逐轮暴露独立问题。工具回执保留结果、可定位差异、拓扑问题、图像和下一步，重复检查说明共用一份；完整原稿、采用值、诊断和审计仍通过单一完整回执引用及read_plan_draft按需读取。此处不改变runtime缓存参数。

独立reader_unit父级只从唯一工具定义构造器生成不可执行目录，保留目录哈希、版本封印、权限/预算与来源审计，不启动没有业务调用的调度员MCP进程。实际读图员仍使用隔离readonly MCP。正常整案的调度员与并发路径继续走原入口；单节点优化不能当作整案提速证据。


保留的单模型实验入口中，平面交付复用现有草稿、源BIM、标定与实际源回叠；立面交付保留独立观测、采用值、标高/开口清单、回叠和未确定项。`prepare_elevation_reading` 复用分工读图校验、墨线定位与10cm规整；等价锚点对、开口列表顺序由代码整理，可从完整清单计算数量，语义冲突仍拒绝。`apply_elevation_readings` 复用匹配与有依据的高度批量应用，应用前返回超宿主高度的开口、楼层和修订入口。

局部判断通过下一次正常建模、修订、读数、装配、应用或交付调用的`reviews_json`携带；没有独立登记工具。判断绑定已返回且模型已检查的结果，不能预先批准该次操作的新结果。先看整套图确认公共坐标和有依据的层高，再尽早试建。建筑判断可随`finish_bim`提交；正式交付前应先完成预期修改和备注整理，再选择实际最终稿。层间轮廓投影差异作为事实提示，不判断同墙、不自动移动墙，墙带规整仍待讨论。

单模型局部检查绑定原图、采用结果和实际回叠；未改的物理范围可跨候选复用，修改高度不作废平面XY判断。装配后重点核对跨图冲突、体量/楼层、空间与动线、宿主和高度合理性，发现具体问题才返回相应图纸。`finish_bim` 对启用该政策的单模型运行要求当前局部覆盖、平立面应用一致性和建筑判断；分工模式使用上述读图交付、装配和建筑判断契约。模型自报检查完成、确定性一致、独立质量评价分别记录；原图已返回不等于模型已正确理解。历史manifest保留原政策。

图纸分工采用 10 cm 规整。整图标注自动选步长、照片/混合输入细度政策仍待讨论；正确空间关系优先于逐点吻合。离线通过不证明图纸保真或推断合理。

## 当前与历史入口

用户入口为 `sim_bim.py` / `Start.cmd` → `product_cli` → `runtime_configuration` → 单模型或分工入口。当前模型实际接收的 guidance 由 domain 模块生成，源码导航见 [domain 入口](../../src/agent/README.md)。

旧 EnergyPlus intake 顺序管线与阶段资源集中到 [legacy](../../src/agent/legacy/README.md)，不作为顶层 skills 或当前 BIM Agent 的步骤说明。历史 stage ID、产物目录与字段保留原含义；共享的几何、校验和下游适配按能力保留，不因历史命名批量删除。继承与新增关系见 [domain 沿革](domain_lineage.md)。

## 程序与数据

D 盘开发仓库含代码、必要测试和当前文档；桌面为固定提交生成的独立产品。`input_root` 只授权本案材料，`run_root` 指向独立产物。GT、历史答案和归档不得暴露给 work model。

完整持久交互编辑界面、各输入的稳定质量、真实模型推理和下游仿真仍需独立验收。历史资料位置见 [归档索引](../reports/archive-index.md)。
