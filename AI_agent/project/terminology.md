# 名词规范

**状态：沿用既有专业术语，按 2026-10-11 讨论修订模型选择、研究线与阶段含义。** 当前约定见 [模型与输入策略](model_and_input_strategy.md)。新写文档、代码和报告按职责表述，历史原文单独保存。BIM 里各构件怎么起名（F1、房间名、逆时针编号）是另一回事，见 [BIM 命名](../design/bim_naming.md)。

2026-10-19补充：用户称最高调度员为 orchestrator，表示掌握全局目标、输入和建筑状态并自主调用worker与工具的职责；沿用“调度员”称呼，当前代码中的coordinator名称不因此变更。旧表中按层/立面派工是现有图纸实现，不限制新mesh路线的自主任务拆分；输入类别也不预设必须量测或固定角色步骤。

用法：一个概念只用一个称呼。第二节的产品结构代号在中文里直接用英文，不再译回中文；其余词用中文称呼，英文名供代码使用。已有的旧标识符写在“指什么”里，不为改名去改旧代码。“不再用”一栏是容易混的旧说法。

**10-08 用户重申：以后汇报都使用本表已确认的术语。** BIM Agent、work model、dev model、harness、runtime、domain 及其组成直接用约定名称；运行方式说“单模型模式／分工模式”，角色说“调度员／平面读图员／立面读图员”。可以附白话解释，但不另换近义称呼。介绍一次实测时，明确 work model、runtime、domain、模式与本次改变的部分，并区分计划与已启动的运行。

## 一、五条总规则

1. **单说“模型”只指 AI 模型。** 建筑模型一律说 BIM（源 BIM、轻量 BIM），不说“源模型”。
2. **“档”必须带前缀：** 模型档（1–5 档）、细度档（精细档／粗档）、思考档（low 到 max）。
3. **“声明”拆成三个词，单说“声明”不再用：** 建筑概况（用户填的结构化信息）、定位观测（claim，模型记的带位置的观测）、建模声明（模型写给代码展开的结构化描述）。
4. **研究线描述信息充分程度，能力描述内部组织。** 还原、部分推理、完全推理不是三套流水线。当前运行和开发计划不沿用固定 0–5 编号；旧编号仅用于明确标记的历史记录。阶段若使用，应直接写明实际任务内容。
5. **包代号和运行编号只在工程记录里用。** C4、D1i、run7 这类写在工作记录与验收里；对用户汇报按内容说做了什么。

## 二、产品结构（10-07 用户定代号）

```
BIM Agent = work model + harness
harness   = runtime + domain
domain    = BIM rules + kernel + tools + methods + roles + guidance
```

runtime 与 domain 的分界是“懂不懂建筑”：runtime 是基础设施，domain 决定任务做得好不好，是长期开发的主要对象。平时说“这个包只改 domain，不碰 runtime”。

| 代号 | 中文解释 | 指什么 | 不再用 |
|---|---|---|---|
| BIM Agent | 建模 Agent | 本项目的产品：把一栋楼的各种资料变成轻量 BIM 的那一个 Agent。还原、部分推理、完全推理都由它完成 | 总 Agent、管线；“统一 Agent”只作强调 |
| work model | 工作模型 | BIM Agent 运行时用到的全部模型：担任角色的 LLM、VLM，以及作为工具调用的 OCR 等专用模型；按任务能力、稳定性、时间和成本选择 | 产品模型、运行模型、生产模型 |
| dev model | 开发模型 | 做开发的模型，包括 Codex 当前主助手及其按需派出的 GPT 子代理；Claude 恢复后也可由 Codex 按需安排。dev model 亲自跑一次建模时，结果仍与 work model 分开报告。按用途分、不按型号分：同一型号在产品里用就是 work model | 开发助手、开发子代理 |
| harness | 工作套件 | work model 以外让 BIM Agent 完成任务的全部支撑（09-14 所说的“工作 kit／harness”）＝ runtime ＋ domain | 工作 kit、kit |
| runtime | 运行底座 | 与建筑无关的基础设施：调用模型、执行工具、派子代理与并发、上下文与缓存、事件日志、预算与恢复（`src/agent_runtime`）。不含建筑知识，但只为本项目的用法打造：不带编程类指令与工具；有图片按引用、按角色配模型、读图员并发、检查点恢复、保护线、完整行为记录。与 Claude Code 对照时也叫新底座 | 基座、底座核心 |
| domain | 建模能力层 | 与建筑有关的全部部分，质量与研究贡献所在（主要在 `src/agent`、`scripts/tool_scripts`） | |
| BIM rules | BIM 规则 | 源 BIM 的结构和修改规则、依据与需求记录、建模声明格式、检查与规整、覆盖清单 | 建筑共用层、建筑层、BIM 层 |
| kernel | 几何内核 | 确定性的几何计算：编译、装配、挂门窗、规整、切配（主要在 `src/agent/geometry`） | |
| tools | 工具 | 模型能调用的功能：看图、量测、试建、建模、修改、检查、交付；每个角色有自己的工具目录 | 工具箱 |
| methods | 方法模块 | 针对输入与任务的可复用做法，可由工具、角色、产物契约和指引共同实现；按问题组合，不按研究线固定，也不等同单段 prompt | 读图方法（泛称时） |
| roles | 角色 | 规定有哪些角色、各干什么、用什么工具、交什么产物；“怎么派、怎么并发”归 runtime。现有调度员、平面读图员、立面读图员；在议：核对员 | 子模型 |
| guidance | 指引 | 写给模型看的全部文字，分五种：系统提示、任务说明、参考资料（`get_bim_reference`）、工具说明、工具反馈 | 指令层、说明层、操作指南、工具说明书 |

|---|---|---|---|

## 七、运行与开发流程

| 中文 | English | 指什么 | 不再用 |
|---|---|---|---|
| 运行 | run | Agent 执行一次任务，如“sm24 run7” | |
| 单模型模式（简称单模型） | single-model mode | 一个 work model 在一条对话里包办全部工作（`mode: single_model`）；与分工模式共用 domain，可作对照 | 单驱动 |
| 分工模式 | role-division mode | 调度员加各读图员分工完成（`mode: role_division`） | |
| 读图任务 | reader task | 调度员派给一个读图员的一份工作：目标（楼层或立面）、原点、可选说明（至多 400 字符）、返工时的问题（`delegate_readers`） | 派工（产品场景） |
| 试建 | trial build | 读图员提交前，用同一套编译与检查试建本层，不存入全楼稿（`trial_plan_bim`） | |
| 提交 | submit | 读图员把产物交给调度员（`submit_plan_reading`、`submit_elevation_reading`） | 交付（读图员场景） |
| 一步建楼 | one-step assembly | 调度员一次调用完成选产物、定标高、逐层建、多层总装、立面对位、写高度（`assemble_from_readers`），只把对不上的交出来 | |
