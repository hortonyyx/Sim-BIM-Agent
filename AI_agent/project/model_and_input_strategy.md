# Work model 与输入能力策略

2026-10-19 更新：公共底座共用，mesh混合输入、可选同模型只读worker、曲线/斜边模板、楼层孔洞、原mesh截线和比较已接通，开发domain121/runtime31。100m内单体办公案例利園六期已备原mesh、23/F图和带来源文字，补入助手按用户授权代拟的简短中文任务说明；实际预检ready，尚未调用真实模型。固定桌面仍runtime24/domain110。实现与质量边界见[最新交接](../reports/2026-10-19_lee_garden_six_mixed_ready.md)。

## 模型、角色和工具包的组合方向

2026-10-19用户确认长期方向：调度员根据目标和证据拆分任务，再选择合适的模型执行某种角色，并为其配置合适的工具包。模型、角色和工具包分别演进；分立面观察、平面理解或几何核对等是可考虑的任务组织方式，不预先要求每栋建筑按固定分面或顺序执行。

- 模型是可替换的执行能力，按实际任务表现、速度和成本选择。
- 角色规定职责、输入/输出、权限与完成条件，不等同某个模型型号。
- 工具包提供角色执行任务所需的可调用能力，可复用公共观察、量测、建模和检查工具。

当前实现仅部分达到该目标：底层模型适配、角色权限与工具适配已分离，产品仍使用预设组合。Mesh调度员可以自主拆问题、选择证据/候选快照和子预算；worker继承主模型及参数，使用固定只读观察角色与工具集合，不能在每个任务中动态改选模型、角色或工具包。任务文字可指定某个立面，但尚未实现专门的分立面角色和对应产物合同。图纸线已有平面/立面读图角色及按角色模型配置，这些不代表mesh已接入相同分工。本轮只记录设计方向，不扩展运行编排。

文字说明已可通过building_input JSON对象进入同一输入与冻结机制；本案临时采用自然语言task_brief与带来源事实并存，标注助手代拟身份。后续统一设计面向还原、部分推理和完全推理、并供图纸/mesh/照片/草图等输入共同使用的说明形式，重点表达目标、材料含义、适用范围、确认/推测/未知和简化要求。当前字段仅作本案载体，不冻结为通用产品schema；用户说明也不承担模型路由或固定流程配置。

## Work model：按任务表现选型

- 不设国别、参数规模和固定型号上限。现有图纸主线基准保留 GPT-6 Sol（`gpt-6-sol`）；新mesh路线初期允许6 Sol/6.1 Sol，具体配置按实测范围确定。Mesh当前建筑规模目标5–10分钟，常规建筑15分钟内，提速优先，再降低消耗与依赖；这些是性能目标，不自动成为质量硬截止。远端API表现和本地资源/速度分别验证，不能按参数规模或Flash名称直接推断部署收益。
- 当前已完成一次6 Sol分工整案，后续以保留够用精度、减少端到端耗时与消耗为准；单次完成不代表成熟稳定。Haiku/27B宽预算小批已结束，质量结论与速度评价分开保留，当前不继续专项调优。
- 五档仅是通用能力的粗略交流方式。读图、三维理解、结构化表达、工具使用和纠错能力须分别通过任务实测判断；不同版本也可能有显著变化。
- 不把某一型号、版本、参数规模或固定组合当长期研究目标。候选持续不适合任务时先换模型，不为保住它持续增加特殊规则。
- harness 的价值是帮助可替换的模型更可靠地交付：保留有效方法、确定性计算、状态与反馈，减少重复摸索。SOTA 单次完成某例仍可作为标杆；harness 的质量、效率与经济性增益需同条件实测。
- 27B旧六节点短预算仅正式交付北/南立面。最新domain111给一平一立每图60分钟/128请求：F1在32分37秒正式提交但有漏开口、错空间与连通；North在7分22秒因工具参数JSON不合法终止。宽预算仍未通过主线替代验证，不能把有稿、缓存命中或数量相同当作质量通过。Haiku最新平面首请求传输失败按授权跳过，North流程缩短但回叠错位仍在，详见当前交接。

图纸线当前按分工设计：平面和立面读图分别交付结构化二维数据、净图与回叠，在读图阶段完成局部正确性检查；组装物化并检查确定性一致性，调度判断整栋合理性，按需返回原图。正确性由读图员还是另一模型检查、是否增加组装员后续再议。domain111已明确图种并使读图参考入口按角色提供，立面不再收到平面朝向说明或跨图匹配方法；调度员和单模型能力指纹未变。分工默认8并发、共享预算与恢复保留。当前单模型支持不限整案时间，分工入口仍要求有限seconds；能力上限测试给宽裕保护预算、完成即停。质量、墙钟时间、消耗、失败和返工分别报告。

**历史安排（2026-10-12，已由上述2026-10-13决策取代）：** 当时用户明确先做 GPT 家族混合分工基线：GPT-6 Sol 协调，GPT-6 Luna 分别读平面与立面；成功后按角色逐个替换 Luna 为27B等候选，再尝试用 DeepSeek Flash、GLM Flash 等替换协调员，每次观察难点适合改harness还是换模型解决。不预设各模型在所有角色上严格强弱排序或换后一定更便宜。当前仅批准接入与sm25首轮，效果很理想时再降低思考档位复测；后续国模批次尚未启动。dev model 只观察和记录，不介入建模，具体配置与预算见[本轮记录](../reports/2026-10-12_sm25_gpt_mix/README.md)。旧外部 Sol 开发会话不等于这次自有 runtime 标杆，账号授权和目录读取也不等于真实推理验证。

## 三条研究线与内部能力组织

还原、部分推理、完全推理描述**输入相对于交付目标的信息充分程度**，不是三个内部子系统，也不与输入模态一一对应。同一栋建筑的不同部分可以同时涉及还原和推断。

内部按可复用任务能力组织：输入盘点与证据定位、图纸识读、网格几何与尺度理解、缺失信息推断、源 BIM 编译与装配、核验与交付。这是能力划分，不要求每项各设一个角色或服务。角色承载上下文、工具与产物契约；runtime 负责执行、并发和恢复。各能力共用源 BIM、BIM rules 和 kernel。

整体网格加标准层平面可分别提供外部体量与局部内部结构，其余部分保留假设；手绘几根线也可仅表达空间关系。输入形式不决定量测要求或精度，同一张图可混合提供可靠尺寸、粗比例和关系示意，由最高调度员理解用户意图后自主选择方法。文字声明帮助交代建筑概况，不是固定流水线配置表。混合输入、直接工具工作和可选worker已有离线闭环，真实模型自主规划、协作质量与速度尚未验证。

Mesh外部质量优先检查整体几何与窗位，内部以合理组织和连通为主。两次旧6 Sol/6.1 Sol产出已获用户整体接受，细度足够；一窗一房、普通门偏置和固定房间数均不作为通用通过条件。建筑类型、门位等常识作为有条件的公共参考，具体布局由模型结合证据判断。

## 开发顺序

1. 当前框架与利園六期混合输入已准备到首次真实完整测试之前，沿用runtime31；固定桌面runtime24/domain110保持，历史证据按原版本保存。
2. Mesh方法与验收独立推进，共用源BIM与工具。已有通用只读worker，后续结合实际任务设计分工、角色合同和模型/工具包组合，避免预设机械流程。
3. 曲线离散、斜边模板和真实空间围合孔洞已接入；通用自动对应/配准、连续斜墙/变截面等尚未完成。分面/分块、标准层复用和CV均为可选策略，已实现与待验证分别记录。
4. 本轮只补简单中文任务说明；跨研究线、多输入形式的说明交互和公共schema留待专门设计。首次真实测试范围、模型、预算已有配置，本轮不启动；图纸整案、国产候选批次与纯照片生成不自动扩测。

新增能力以实际输入、可调用工具、可检查产物及案例结果为准。调度员自主决定亲自处理或委派，不要求预先配齐角色或枚举所有建筑场景。

## 留待讨论：照片路线与建模细度

用户关注“照片 → 生成 textured mesh → 复用 mesh 处理 → 源 BIM”，以减少直接从照片编写 BIM 对 work model 三维推理的要求。已有 Figure 15 独立原型使用图像处理和 Hunyuan3D 3.1，再由开发代理重建 IFC 并转换为项目源 BIM；它含外部面积/窗墙比标定和内部假设，不是纯图片自主还原或生产 harness 能力。原始产物保留在 D盘 runs，详见 [照片路径记录](../design/photo_to_mesh_bim.md)。

信息少时可考虑更粗的源 BIM，例如一层一个空间块、仅在明显体量变化处分块，避免必须补全房间级内部布局。**本轮明确将这一方案及细度调整留待继续讨论**：没有把“一层一个块”设成默认值，也没有更改源空间合并、开口、10 cm 规整或交付检查。

已确认由调度员依据用户目标和各部分证据选择处理方法与必要精度，不因附有图纸而自动进入精细量测。具体简化表达、模板交互和数值容差在搭建时收敛；纯照片生成网格与原图冲突的处理仍留待该路线恢复时讨论。源空间细度与下游热区划分继续分开。
