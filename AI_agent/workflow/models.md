# 开发与产品运行的模型约定

当前策略以 [模型与输入策略](../project/model_and_input_strategy.md) 为准。本页只保留有效规则；逐次用量、旧型号限制和历史分工保存在 [归档索引](../reports/archive-index.md) 所列快照和原实验中。

## Work model 选择

Work model 不设国别、规模或型号上限。当前主线使用 GPT-6 Sol（`gpt-6-sol`），调度/平面high、立面medium，不以6.1 Sol替代。用户当前要求在既定Lite精度下越快越好，平面3–4分钟、整案约5分钟是优化目标，不是质量硬截止；分工采用runtime默认8读图并发，共享预算和恢复保留。Haiku先完善角色包并用宽裕预算看能力上限，再试27B；外部传输问题暂不追查，不把历史600秒/16请求自动沿用为上限测评标准。范围、角色、模型和保护预算在实际启动前明示；后续意向不等于已经启动。实测边界见[当前交接](../project/roadmap.md)。五档仅为粗略交流标签，不是建筑任务排名或准入名单。

通过调研和任务实测更新选型，比较空间/几何质量、有效交付时间、总 token/费用、失败和返工、工具使用及适配负担。不适合任务的模型可以替换，不为冻结版本持续增加特殊规则。27B 的局部良好表现是候选依据，不等同整案稳定。

真实批次运行前公开配置与验收范围，保留当前会话授权依据；Dev model观察、分析和记录，开发辅助、独立work model冷启动与确定性重放分开报告。历史27B每节点600秒只代表当时的限额结果；新的能力上限测试先给足时间和请求，速度另行评估。来源、拓扑、宿主和正式提交的完整性检查仍保留，不以放宽预算替代质量要求。

## 服务与配置

配置见 [model_configuration](../design/model_configuration.md)。同一型号在不同服务上的模态、工具协议、限流、思考与计费可能不同；以明确 profile 和真实回执为准。历史价格、余额与目录不作为当前事实。

OpenCode Go现以独立`opencode-go`订阅路由接入，可用于单模型和图纸分工；明确协议/参数的六个型号与凭据文件说明见 [Go接入](opencode_go.md)。它与Paratera的按量线路分别记录，不共用价格表或自动互相回退。目录暴露、协议接线、工具/图片闭环和建筑质量分别报告。

用户已完成 Sim BIM Agent 独立 ChatGPT 授权，开发与桌面产品已读取模型目录；本地严格 profile 已包含 `gpt-6-astra`、`gpt-6.1-sol`、`gpt-6-sol`。6 Sol已完成一次sm25自主分工整案，不能据此宣称稳定成熟；账号当前可用性以实际服务回执为准。历史授权核验见 [授权记录](../reports/2026-10-11_repository_subscription_auth.md) 与 [接入说明](chatgpt_subscription_runtime.md)。

## 调用权限与费用

- 真实模型测试按本次明确范围执行。旧批次授权、目录读取、登录与普通开发授权不自动扩大到新整案。
- 订阅在已授权范围内使用；不可用时不自动回退按量服务。
- **DeepSeek 每次/每批须获用户明确许可**，涵盖开发、子调用、探测、重试和回退；旧配置有凭据不构成许可。
- 不自动切换未授权平台、收费线路或账号。密钥只注入所需进程，不进入提示、报告、仓库或发布包。
- 供应商实报、runtime 估算、CLI 估价和账单分开；未知 usage/费用保留未知，不重复计造缓存或图片用量。
- 测试正文用表格报告质量、耗时、调用、用量、干预和未覆盖项。提交成功与独立质量通过分开。

## Dev model 与协作

Codex 当前主助手负责技术取舍、实施组织、验证、文档和正常 commit/push，具体型号不作为长期身份。开发模型与 work model 的消耗和成果分开。是否派子代理遵守当前会话指令，不因历史安排自动派工。

历史成功和失败追溯到原 run、版本和报告，不仅引用模型名称。本页不保存实时余额或固定价格。
